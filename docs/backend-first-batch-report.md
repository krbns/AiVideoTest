# Подключение backend: порция B1

7 октября 2026. Основа: commit `832a44e`, Android / Jetpack Compose. Контракт: [Benvilo Swagger](https://benvilo.shop/docs#/) и сохранённый OpenAPI `backend/benvilo-openapi-2026-10-07.json`.

## Результат

Приложение подключается к серверу, восстанавливает сессию и показывает реальные каталоги фото/видео, модели, баланс, профиль, права аккаунта, продукты и историю. Демо-сценарии сохранены. В серверном режиме неизвестный баланс обозначается «—», ошибка не создаёт демонстрационные кредиты или результаты.

Для проверки установить `AiVideoTest-backend-B1.apk`, пройти прежний onboarding и открыть **Settings → Connect to server**. Кнопка подключения доступна в debug-сборке. В серверном Settings кнопка **Back to demo** находится после списка продуктов; выбранный режим сохраняется между запусками. **Refresh** повторно загружает данные; при истёкшей сессии использует предусмотренное API получение токенов для той же установки и того же аккаунта.

Release собирается, но сохраняет прежний демонстрационный вход. B1 — основа подключения и просмотра; серверная генерация, оплата, push и действия с результатами ещё не подключены. Кнопка Use this effect в серверном режиме отключена, Prompt показывает каталог моделей и поддерживаемые разрешения/длительности. Серверные товары отображаются без кнопок покупки и без вымышленных локальных цен.

| Продукты | 7 |

Профиль и policy также загрузились: подписка неактивна, осталось одно пробное использование. Это текущее состояние отдельного тестового аккаунта, а не начальные значения, зашитые в приложение.

Проверено отображение серверных обложек, моделей, пустой истории и аккаунта. После остановки процесса и нового запуска сессия и каталог восстановились. Избранный серверный видеоэффект сохранился после перехода в демо и повторного подключения. Демо снова показало свой прежний каталог и баланс 5; при возврате на сервер отобразился серверный баланс 0. Запросы генерации, upload, платежей, webhook и admin не выполнялись.

## Сессия и данные

- Регистрация выполняется по стабильному deviceId установки; существующая сессия переиспользуется. Refresh синхронизирован внутри клиента, оба новых токена сохраняются вместе до следующего запроса. Повтор после HTTP 401 допускается только для чтения.
- DeviceId и токены хранятся единым зашифрованным AES/GCM-record с ключом Android Keystore. Хранилище сессии и выбора режима исключено из cloud backup и device transfer. Ошибка хранилища не создаёт другой аккаунт автоматически. Проверяется совпадение userId/deviceId после обмена токенов.
- API использует HTTPS и ограниченные таймауты/размер ответа. Bearer не отправляется при загрузке обложек и не пересылается через redirect. Диагностика и ошибки не выводят JWT, refresh или полный приватный ответ.
- Ответы чтения кэшируются атомарно в каталоге cache по userId. Сохранённые данные и баланс отмечаются в UI; ошибка одного раздела позволяет показать остальные. Очистка Android-кэша может удалить этот кэш, но не сессию.
- Избранное локальное, привязано к серверному аккаунту; синхронизации между устройствами нет. В B1 история загружается страницами всех типов, фильтруется локально и объединяется по jobId. Опрос активных задач и открытие/экспорт результата относятся к B2/B3.
- DTO и сетевой контроллер находятся отдельно от demo. Прежние demo-модели, экранные сценарии и Android-контракты выбора/экспорта сохранены; тема и основные пять вкладок переиспользуются. Новых SDK-зависимостей нет.

## Проверки

| Проверка | Результат |
| --- | --- |
| Debug и Release | Обе сборки успешны |
| Unit tests | 33, без ошибок и пропусков |
| Device tests, Android 14 / API 34 | 58, без ошибок и пропусков |
| Из них новые B1 | 9 contract/storage/controller + 3 Compose UI |
| Lint debug | 0 ошибок, 39 предупреждений, 1 hint |
| Структура ресурсов и diff | XML разобран, имена строк уникальны, diff без ошибок пробелов |

Новые тесты проверяют регистрацию без повторного создания, ротацию токенов, один refresh для двух параллельных 401, отказ refresh без смены аккаунта, запрет смены identity, nullable/неизвестные поля, оба формата 422, HTTP 200 blocked, восстановление зашифрованного хранилища, изоляцию кэша и частичный отказ разделов. UI-тесты проверяют неизвестный баланс, восстановление через demo, реальные стоимость/число фото и отключённую генерацию, отметку кэшированного баланса и пагинацию истории.

Четыре новых lint-предупреждения в backend относятся к рекомендации UseKtx для SharedPreferences. Они не блокируют сборку. B1 проверена на API 34; прежняя проверка demo на API 36 не считается проверкой этой интеграции. Реальную ротацию истёкшего токена, непустую историю и генерацию живой серверный прогон не проверял; эти случаи либо покрыты контрактными тестами, либо остаются следующими этапами.
