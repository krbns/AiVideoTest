# Серверный запуск и восстановление

Дата: 9 октября 2026. База: `e989707`. UI — Jetpack Compose. Изменения этой порции сохранены отдельным коммитом.

## Изменения

- Новый запуск сразу открывает серверный workspace и восстанавливает защищённую сессию. Debug сохраняет явно выбранный demo; release всегда использует сервер, в том числе после обновления debug-установки с сохранённым demo. Существующие аккаунты не сбрасываются.
- Кэш GET-данных загружается до сетевой авторизации, но только по идентичности из зашифрованного хранилища. Пока сессия проверяется, разделы остаются в состоянии загрузки; после ошибки сохранённые каталог, профиль и баланс доступны с соответствующим статусом. Нечитаемая идентичность не приводит к автоматической регистрации другого аккаунта.
- Перед обменом одноразового refresh-токена синхронно сохраняется `refreshPending`. Потерянный ответ или завершение процесса не вызывают повтор старого refresh. Пользователь видит Reconnect; это `/v1/auth/token` для прежнего deviceId с проверкой прежнего userId. Полная новая пара токенов сохраняется до её использования. Старые сохранённые сессии без нового поля поддерживаются.
- Возврат в приложение запускает ограниченное по частоте обновление GET-данных: после ошибок — не чаще 15 секунд, обычное обновление — после 60 секунд. Это не повторяет генерацию, удаление, отмену или оплату.
- Поздний ответ опроса задачи после ухода приложения в фон игнорируется. При возврате опрос продолжается по сохранённому jobId. Известные задания и неопределённые отправки восстанавливаются прежним безопасным сценарием, без автоматического платного POST.
- Исправлен реальный сбой release на Android 24: существующая частичная R8-оптимизация создавала недоступный superclass Kotlin (`IllegalAccessError` при AndroidX Startup). Используется полная R8-оптимизация; инструменты и зависимости не обновлялись. См. [документацию Android](https://developer.android.com/topic/performance/app-optimization/optimize-specified-packages).
- Android 7 не принимал HTTPS API из-за отсутствующего trust anchor. Добавлен официальный ISRG Root X1 только для `benvilo.shop` на API 24–25. С API 26 ресурс конфигурации использует системное хранилище. HTTP запрещён, проверка сертификата и hostname сохраняется. Источник: [Let's Encrypt](https://letsencrypt.org/certificates/), конфигурация: [Android Network Security Configuration](https://developer.android.com/privacy-and-security/security-config). SHA-256 DER: `96bcec06264976f37460779acf28c5a7cfe8a3c0aae11a8ffcee05c0bddf08c6`. Доверие этому root следует пересмотреть при смене CA API или обновлении минимальной версии Android; это не pinning leaf-сертификата.

## Проверка

Debug и release собраны; unit — 35/35; lint — 0 ошибок, 53 предупреждения, 2 hint. Android 24 — 60/60, Android 28 — 60/60, Android 36 — 123/123; после последнего изменения изоляции тестовой фикстуры дополнительно повторены 3/3 media-теста на API 36. Основной APK при этой правке не менялся.

Native release автоматически загрузил серверный каталог на всех трёх API; холодный запуск сохранил тот же аккаунт. На API 24 системная камера создала фото, редактор импортировал его, а окончательная release-сборка восстановила референс после завершения процесса. На API 28 и 36 открылись системные picker и корректно обработали отмену. На API 36 холодный офлайн-запуск сохранил профиль/баланс с пометкой saved; возврат после включения сети автоматически обновил данные прежнего аккаунта. На старом API 24 команда AVD `svc wifi` завершалась с кодом 137, поэтому native отключение сети проверялось на API 36; контролируемые offline/expired/cache-сценарии прошли на всех трёх API.

Первоначальные попытки выявили и помогли исправить release IllegalAccessError, TLS trust anchor и преждевременную готовность из кэша. Отдельно устранены ошибки тестовых фикстур, совместимость чтения/перехвата Share и загрузка ненужного demo-каталога при media recreation на Android 24. Исходные crash/TLS-логи сохранены отдельно от успешных итоговых логов.

Результаты и перечень файлов: [validation.json](backend-startup/validation.json), [changed-files.txt](backend-startup/changed-files.txt).

Новые проверки покрывают автоматический вход, явный debug-demo, серверный release, сохранение аккаунта и кэша при истёкшей сессии/сети, сохранение маркера refresh в зашифрованном хранилище, отказ записи маркера до HTTP, повреждённую идентичность, частоту foreground GET, запрет повтора POST после 401 и поздний ответ приостановленного polling. ActivityResult-проверки покрывают камеру через FileProvider, нормализацию выбранного фото, маршрутизацию фото в video-редактор, recreation, отмену и удаление временного capture-файла.

Тестовый runner явно изолирует demo/контролируемые ответы от реального API. На API 24–28 проверка сохранённых MediaStore-байтов выполняется независимым shell-чтением; приложение не получило широкое READ-разрешение. WRITE-разрешение для автономных export-тестов выдаёт runner. Share chooser перехватывается без отправки получателю; callback Intent доступен с API 26, на API 24 проверяются реальный запуск заблокированного chooser и байты файлов отдельными media-тестами.

Native-проверки проводятся на отдельных временных AVD. Пользовательский эмулятор не изменяется. Реальные платные генерации, отмена/удаление серверных задач, покупки и отправка медиа получателю в этой порции не выполнялись.

## Контракт и ограничения

Свежая [OpenAPI](backend/benvilo-openapi-2026-10-09.json): SHA-256 `f8f5d1af522e8e4db37f5de13da97a3f6ecc11274bf861551866326130725352`. Проверены описания register/token для прежнего deviceId и одноразового refresh. От предыдущего снимка изменились описания progress, multi-image video и AI Tools/audio-схемы; обязательные поля реализованных photo/video-запросов не добавились. Новые audio/tools-сценарии остаются отдельной порцией.

Покупки/restore и Adapty, FCM, приём обращений, юридические URL и лицензированный SF Pro остаются отложенными. Физическое устройство и API 37 в этой порции не проверяются. Восстановление сохранённой установки не означает перенос аккаунта после удаления приложения или на другое устройство: для этого нужен отдельный согласованный сценарий авторизации/переноса. Нулевой баланс нового тестового аккаунта отражает серверные wallet/policy, клиент не начисляет кредиты.
