# B3 — Video Prompt и Effects

Дата: 8 октября 2026. База: `987c294`. UI: Jetpack Compose, существующая дизайн-система. Коммит и push не выполнялись.

## Что добавлено

- Video Prompt: textToVideo / imageToVideo, выбор только совместимых моделей, параметры текущего режима, длительность, resolution, aspect ratio и звук из каталога. Цена рассчитана по каталогу с округлением вверх; фактическое списание показано из job. Один запуск создаёт одну server job, двойной tap блокируется.
- Photo / Video Effects: форма по templateId, точное число пользовательских фотографий, серверная цена tokens. Скрытый prompt и настройки не копируются в клиент; POST передаёт только templateId и imageUrls. Серверная цепочка image_video — один POST /videos и одна job, клиент показывает этап.
- Раздельные журналы photo/video на аккаунт. Известная задача восстанавливается через GET; неопределённая отправка ищет совпадения в свежей истории kind=video. Выбор и detail-проверка требуют явного подтверждения; платный POST не повторяется автоматически.
- Video Result: проверка и скачивание MP4/MOV на диск, постер, локальное воспроизведение, Play/Pause, пауза при уходе в фон, сохранение позиции при пересоздании. Ошибка кодека предлагает повтор воспроизведения, не новую генерацию.
- Gallery / Files / Share используют исходные байты результата без перекодирования, отдельный журнал экспорта и существующие Android-контракты. Исходный контейнер определяется по файлу, а не расширению URL или необязательному MIME сервера. Кэш с проверенными байтами работает после истечения ссылки; без кэша истёкшая ссылка выдаёт ошибку.
- Cancel queued/running и Delete completed/failed — отдельное подтверждение, одна мутация. При потере ответа выполняется GET сверки. Возврат кредитов отображается только по серверному creditsRefunded.
- «Review a new generation» открывает черновик для проверки. Новый платный запуск происходит только отдельным нажатием Generate / Use effect.
- Library открывает обе разновидности результатов. При восстановлении двух известных отправок открывается последняя по сохранённому времени; пересоздание экрана не перенаправляет повторно с выбранного пользователем раздела.
- В серверном профиле добавлен отдельный Credit balance: ранее сумма была только в верхнем бейдже. Карточка и бейдж используют один источник — wallet.balance, с резервом policy.creditsBalance. Ноль отображается числом; загрузка, отсутствие данных и сохранённый баланс различаются, повторное чтение доступно через Refresh. Ответ /profile содержит имя и accountId, а не баланс.

## Архитектура

Переиспользована цепочка B2: BackendClient, auth refresh lock, PhotoGenerationController, PhotoRequest, PhotoJournal, RemotePhotoEditor/Result и ExportController. Имена общих классов оставлены для совместимости с существующим кодом и тестами; kind различает image/video. AppViewModel владеет двумя независимыми экземплярами, журналы — backend_photo и backend_video. DemoSession и демонстрационные финансы не участвуют в server-режиме.

Видео скачивается потоково с ограничением 512 MiB. HTTPS-загрузка ассета не получает bearer сессии, учитывает срок действия и ограничивает redirects. MediaMetadataRetriever проверяет наличие видео, размеры и длительность; плеер получает только локальный проверенный файл. Auth, журналы операций и фотографии исключены из backup/device transfer.

## Источник контракта

[OpenAPI](https://benvilo.shop/openapi.json) повторно прочитан 8 октября. Он совпал со снимком [2026-10-08](backend/benvilo-openapi-2026-10-08.json): 72 пути, SHA-256 `9bad6a2ce7c9b5d030414c059146a01cd6f5c8a181c25f91d97a5d5916cfdf64`. Дубликат снимка не добавлялся. Настройки и цены берутся из реального каталога, а не из examples Swagger.

Формула video: `ceil(credits × ceil(duration / baseDurationSeconds) × resolutionMultiplier × audioMultiplier)`. Audio multiplier применяется при generateAudio=true; null означает отсутствие влияния звука на цену. Например, 7 кредитов за 4s, 6s, разрешение ×2 и звук ×1.5 дают 42. Цена шаблона — tokens, а не цена модели с самостоятельно восстановленными параметрами.

Платформенные API: [MediaMetadataRetriever](https://developer.android.com/reference/android/media/MediaMetadataRetriever), [VideoView](https://developer.android.com/reference/android/widget/VideoView).

## Неоднозначности и границы

- Нет клиентского idempotency key. Совпадение model/mode/parameters/templateId, времени и референсов не доказывает связь с запросом. Даже единственный кандидат выбирает пользователь.
- У шаблонов inputImageUrls может содержать скрытые серверные референсы или результат первого шага. Сравнивать этот список с пользовательским upload побайтно нельзя; такие кандидаты отмечены как неполные. TemplateId, модель, тип и временной диапазон проверяются, привязка автоматом не выполняется.
- Каталожная цена — оценка; источник фактического списания/возврата — server job. Доступ проверяется по policy, недостаток баланса может вернуть серверный 409. Trial и покупки здесь не начисляют кредиты локально.
- Processing / AI Tools (Enhance, FPS, video extension, Motion Control, Lip Sync, AI Avatar) требуют дополнительных видео/аудио/голоса и отдельных форм. Они не подставляются в обычный prompt-редактор. Неизвестная модель, режим, обязательный параметр или неподдерживаемый шаг отключают запуск.
- Обложки каталога используют серверный poster. Воспроизведение добавлено для готового результата; автоматическое проигрывание всех карточек каталога не включено.
- Покупки, Adapty non_subscription_purchase, push/FCM, sourceJobId из Photo Result и фоновый Android worker для polling не входят в B3. Polling идёт при активном приложении и возобновляется после возврата. Release сохраняет текущий demo-вход; server-вход доступен в debug.
- Пока подтверждён только API 34 на отдельном эмуляторе. API 24–28/36 и физическое устройство требуют следующего прогона; покупок и push тестовая матрица не подтверждает.
