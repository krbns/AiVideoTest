# Восстановление Photo Prompt через историю задач

8 октября 2026. Основа: commit `da54a48`. Android / Jetpack Compose. Покупки, push и видео в эту порцию не входят.

## Поведение

После потери ответа генерации приложение сохраняет UNKNOWN и ищет похожие задачи через свежий `GET /v1/media/jobs?kind=image&limit=20`. История Library и её кэш не считаются подтверждением результата отправки. Поиск доступен после перезапуска; его можно обновить и продолжить следующей страницей с тем же фильтром image. Курсоры кодируются, одинаковые jobId объединяются, повторяющийся курсор останавливает дальнейшее пролистывание с сообщением об ошибке.

Перед POST атомарно сохраняется снимок фактического тела запроса: модель, режим, prompt, настройки, загруженные imageUrls; время отправки и ID задач, известных клиенту до запуска. Снимок переживает закрытие процесса вместе с SENDING/UNKNOWN. Смена редактора для новой генерации очищает прежнее сопоставление.

Подходящий кандидат должен иметь image kind, ту же модель и prompt, тот же templateId (для Photo Prompt — без шаблона). Противоречащие mode, переданные параметры или inputImageUrls исключают задачу. Числовые значения сравниваются как числа; строка «1» не равна числу 1. Лишние серверные defaults допустимы. Известные до запуска задачи исключаются. При наличии createdAt используется окно от пяти минут до отправки до десяти минут после неё, допускающее расхождение часов. Это эвристика, а не гарантия.

Старый журнал без снимка запроса и задачи без части metadata поддерживаются с предупреждением о неполноте сравнения. Их совпадение проверяется по доступным полям. У старого журнала недоступны исходное время отправки и загруженные URL референсов. Отсутствующие данные не выдаются за проверенные; несовпадающие значения исключаются.

Ни один кандидат, даже единственный, не выбирается автоматически. Пользователь видит модель, время создания, состояние, server charge и полный task ID. Выбор открывает подтверждение. После подтверждения приложение делает `GET /v1/media/jobs/{jobId}`, заново проверяет ID, параметры и текущий аккаунт, сохраняет выбранную job и только затем открывает результат. Running/queued продолжают polling; completed использует прежние downloader и экспорт. Отмена подтверждения сохраняет UNKNOWN и не вызывает detail GET.

Пустая история, ошибка поиска, 404 выбранной задачи или изменившиеся детали сохраняют UNKNOWN. Пустая страница не доказывает отказ исходного POST. Новый запуск остаётся отдельным действием после прежнего подтверждения риска повторного списания. Поиск и восстановление не вызывают POST генерации и не начисляют/списывают кредиты локально.

## Ограничения и следующие шаги

Backend подтвердил отсутствие клиентского ключа идемпотентности. Ключ из server jobId относится к уже существующей задаче; он не разрешает безопасно повторять потерянный запрос создания. Идентичные запросы на одном или нескольких устройствах могут иметь несколько совпадений. Временное окно, неполные metadata, серверные преобразования параметров и изменения часов могут не дать найти принятую задачу. В таком случае доступны ручная проверка Library и обновление поиска; автоматической повторной отправки нет.

Снимок содержит URL загруженных референсов только в локальном журнале, уже исключённом из backup/device transfer. Тела запросов, bearer/refresh и приватные URL не включаются в отчёт и диагностические сообщения. Поиск разделён по аккаунтам, результаты прежнего аккаунта не применяются к новому.
