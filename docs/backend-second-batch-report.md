# Backend B2: Photo Prompt и результаты

8 октября 2026, Europe/Moscow. Основа: commit `c40c59d`. Android / Jetpack Compose. Контракт: [Benvilo Swagger](https://benvilo.shop/docs#/) и [OpenAPI](https://benvilo.shop/openapi.json), снимок `backend/benvilo-openapi-2026-10-08.json`.

## Что работает

В debug-сборке: **Settings → Connect to server → AI Photo → Prompt**.

- Редактор показывает только модели с режимами textToImage/imageToImage. Модель, качество, соотношение сторон и формат берутся из server catalog; выбранные значения проверяются по текущему режиму. Начальные значения используют defaults. Предварительная цена вычисляется по resolutionCredits; фактически списанное показывается из job.
- Текст поддерживает серверный лимит 10000 Unicode-символов. Демо-стили не отправляются как вымышленные API-параметры. Обязательная настройка, которую клиент не поддерживает, не позволяет отправить запрос.
- Системный picker и камера используют прежние Android-контракты. Фото сохраняются локально, нормализуются с EXIF-поворотом в JPEG, уменьшаются до 1600 пикселей по стороне. Несколько фото допускаются в пределах min/maxInputImages выбранной модели. Выбор фото сам по себе ничего не загружает на сервер.
- Generate photo последовательно загружает референсы через media/uploads, проверяет ответ и срок ссылки, затем отправляет ровно один application-level POST /media/images. Второе нажатие во время операции блокируется. Явный запрет из policy отключает запуск.
- Известная job опрашивается через GET по ID. Ошибка чтения не создаёт новую job: используется задержка с увеличением до 30 секунд. Polling приостанавливается в фоне/демо и возобновляется при возвращении. Завершение/списание/возврат исходят от сервера; локальных начислений и фиктивного четырёхсекундного результата нет.
- Photo Library открывает серверные изображения и их статус. Результат загружается с публичной HTTPS-ссылки, проверяется как JPEG/PNG/WebP и показывается в приложении. Gallery, Files и Share экспортируют исходные байты этого результата, сохраняя формат и PNG-прозрачность; референс и demo asset в эту цепочку не входят.
- Экспорт переиспользует прежний ExportController и ResultMedia через общий ExportContent. Сохранены Android permissions, SAF, FileProvider/grants, защита от повторного Share и удаление неполной gallery-записи после прерывания. Demo и server используют отдельные журналы экспорта.
- Сохраняются текст, модель, параметры, локальные фото и принятая job. После перезапуска известная job продолжает GET-polling, без нового POST генерации. Серверные журналы/референсы исключены из backup/device transfer.

Release собирается, но вход на сервер пока доступен через debug-пункт Settings. Video Prompt, генерация Effects, видео/аудио-результаты, cancel/delete и оплата/push остаются следующими порциями.

## Неопределённый исход запроса

Перед отправкой генерации в атомарный журнал записывается SENDING. Потеря ответа, HTTP 502/неопределённая 5xx-ошибка или непригодный ответ переводят операцию в UNKNOWN. Это состояние сохраняется после закрытия процесса и блокирует новую отправку.

Приложение предлагает проверить Library и обновить баланс. Оно не сопоставляет похожий prompt с задачей автоматически. Пользователь может отдельно подтвердить, что проверил историю и понимает возможное повторное списание; это только разблокирует редактор. Новый POST отправляется лишь следующим нажатием Generate.

Документированные отказы 401/403/409/422/429/503 показываются как отказ без автоматического повтора. Потерянная отправка uploads не запускает генерацию. Прерывание на стадии загрузки позволяет вручную загрузить локальные фото заново. Серверная идемпотентность по-прежнему не определена.

HTTP-тела передаются в streaming mode без внутреннего буфера и автоматической обработки authentication/redirect. [Android HttpURLConnection](https://developer.android.com/reference/java/net/HttpURLConnection#setFixedLengthStreamingMode(int)) описывает это поведение. Данный механизм не заменяет серверную идемпотентность и не даёт гарантий о действиях внешнего proxy.

## Реальная проверка и её предел

Отдельный тестовый аккаунт **3932-4600-T6F54** первоначально имел баланс **0**, trial **0** и запрет генерации. На Android 14 проверены серверные каталоги, реальные параметры Nano Banana Pro, системный picker, нормализация синтетического референса и ручная попытка при нулевом балансе. Сервер вернул insufficient_credits; задача не появилась, баланс остался 0. После перезапуска сохранились текст, модель, параметры и фото; автоматической отправки не было. Проверка отказа выполнена до добавления UI-блокировки по policy; в финальной сборке известный запрет отключает кнопку заранее.

Позже реальные ответы сервера для этого же аккаунта показали **100 кредитов**, активную подписку и разрешение генерации; trial остался 0. Выполнена **одна платная imageToImage-генерация**: Nano Banana Pro, 1K, auto, JPEG; текст «Create a simple blue ceramic vase on a white background» и синтетическое синее изображение 512×512. Серверная job прошла running → completed, вернула одно изображение PNG и списала **8 кредитов**. После обновления серверный баланс — **92**.

Результат скачан, показан и сохранён в Gallery и Files. Android Sharesheet открылся с изображением; файл для Share также совпал с оригиналом. Получатель не выбирался, внешняя отправка не выполнялась. Экспортированные **310582 байта** точно совпали с загруженным оригиналом: SHA-256 `6a448eaf12120f8a5a6c07d5c873d97166a4404a493a0da7fd9a4c132aecde73`. Полный перезапуск приложения восстановил эту же завершённую задачу, картинку, списание и отметку сохранения. Новая генерация не отправлялась.

**Неоднозначность live-контракта:** запрос содержал outputFormat=jpeg, но полученный файл — PNG 1024×1024. Клиент определяет фактический MIME по декодируемым байтам и экспортирует PNG с правильным расширением без перекодирования. Нужно уточнить у backend, обязан ли провайдер соблюдать outputFormat или этот параметр носит рекомендательный характер.

Оба режима, upload-before-generate, queued/running/completed, перезапуск активной job, потерянный ответ и экспорт исходных байтов дополнительно проверены на контролируемых ответах. Бесплатный trial на реальном сервере не проверялся.

Кэш/журнал привязаны к userId. Bearer не передаётся хосту изображения; JWT, refresh и приватные URL не выводятся в диагностике. Локальная копия позволяет экспорт после истечения URL; незагруженная истёкшая ссылка показывает ошибку. ISO-даты с микросекундами нормализуются корректно. Созданная задача отображается в Library и открывает готовый результат. 404/410, повреждённый файл и неподдерживаемый формат не превращаются в успешный результат.
